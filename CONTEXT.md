# zchemer

Образовательная игра, обучающая языку Scheme в стандарте R6RS. Игрок сначала проходит базу языка, затем выбирает один из продвинутых треков-проектов. Треки можно проходить в любом порядке, но пересечения навыков учитываются в рекомендованном порядке прохождения.

## Язык

**Игрок**:
Человек, проходящий обучение в zchemer.
_Avoid_: пользователь, студент

**База**:
Вводная часть обучения: основы языка Scheme в стандарте R6RS.
_Avoid_: основы, вводный курс

**Трек**:
Продвинутая тема-проект, которую игрок разрабатывает сам: сеть, базы данных, свой интерпретатор, многозадачность, ООП и др.
_Avoid_: модуль, раздел

**Исполнитель кода**:
Встроенный движок, выполняющий и проверяющий код игрока по стандарту R6RS.
_Avoid_ (в значении проверки кода): интерпретатор

**Интерпретатор**:
Трек, в котором игрок пишет собственный интерпретатор Scheme.
_Avoid_: исполнитель кода

**Навык**:
Единица освоенного знания; пересечения навыков между треками учитываются в рекомендуемом порядке прохождения.
_Avoid_: prerequisite, компетенция

## Структура

**Урок**:
Единица обучения внутри трека: текст, пример кода, задание. Порядок уроков внутри трека определён.
_Avoid_: модуль, тема, блок

**Проверка**:
Код игрока проверяется автоматическими тестами, сравнивается вывод. При непрохождении — подсказка.
_Avoid_: валидация, верификация

**Прогресс**:
Состояние прохождения игры: сохраняется локально, доступен для экспорта/импорта в JSON.
_Avoid_: статус, достижение

**Проект трека**:
Рабочее окружение трека на диске; игрок разрабатывает код в нём, приложение проверяет решение через исполнитель кода.
_Avoid_: рабочая директория, песочница

## Принципы

**Треки стартовые**:
Интерпретатор, сеть (TCP/UDP), многозадачность — первые три трека. ООП и БД добавляются позже.

**Мотивация**:
Прогресс прохождения — единственная механика мотивации на старте; очки и достижения не входят в MVP.

**Окружение игрока**:
Код пишется внутри приложения; для треков-проектов игрок также может открыть проект во внешнем редакторе.

**Интерфейс**:
Только на русском языке на старте; англоязычная версия — позже.

**Контент уроков**:
Уроки хранятся в Markdown-файлах, компилируются в бандл приложения. Редактировать контент можно без изменения логики.

**Прохождение урока**:
Урок считается пройденным автоматически — когда тесты прошли. Внутри трека уроки проходятся по порядку, межтрековые навыки лишь рекомендуют порядок, но не блокируют.

**Интерфейс урока**:
Сплит-панели: текст и пример слева, редактор справа, вывод снизу.

**Черновик**:
Ненаписанный до конца код урока. Автоматически сохраняется при выходе из незавершённого урока, чтобы можно было продолжить с того же места, а не начинать заново. Хранение — в прогрессе.

## Технологии

**Редактор кода**:
CodeMirror 6 — лёгкий редактор с подсветкой Scheme, встраивается в сплит-панели.

**Управление исполнителем**:
Две команды: «Запустить» (показать stdout/stderr) и «Проверить» (прогнать тесты, подсказка при провале).

**Формы заданий**:
Только написание кода с автотестами. Иные формы (выбор, сопоставление) — вне MVP.

**Исполнение для треков**:
Встроенный WASM-Chez — для базы и простых примеров. Для треков-проектов (сеть, БД, файловая система) — отдельный Chez Scheme, поставляемый как sidecar в комплекте приложения.

**Настоящий Chez**:
Chez Scheme 10.4.1 установлен локально (`C:\Program Files (x86)\Chez Scheme 10.4.1`) и используется при разработке как исполнитель. Для распространения по-прежнему нужен sidecar, поставляемый с приложением. Для треков с системным доступом sidecar запускает **потоковую** сборку (`bin\ti3nt\scheme.exe`), т.к. только она поддерживает `fork-thread`/`make-mutex`; Резолвер `resolve_scheme_exe` в `src-tauri` перебирает потоковые пути раньше непотоковых (`i3nt`).

**Сокеты (сетевой трек)**:
Напрямую дёргать WinSock из Chez через `foreign-procedure` нельзя: любые stdcall-вызовы ws2_32 выполяются, но процесс Chez падает при выходе. Поэтому sidecar использует C-прокладку `zchm_ws.dll` (`src-tauri/standalone/zchm_ws.c`, собирается `zig cc -target x86-windows-gnu -shared`), которая принимает **cdecl**-вызовы и оборачивает stdcall-WinSock. DLL вшита в бинарь через `include_bytes!`, кладётся во временный каталог и загружается `(load-shared-object <путь>)` перед программой игрока; дружелюбный Scheme-API (`tcp-listen`, `tcp-connect`, `tcp-accept`, `socket-send`, `socket-receive`, `udp-socket`, `udp-bind!`, `udp-send-to`, `udp-receive-from`, `socket-close!`, `local-port`) — в `src-tauri/standalone/sockets.ss`, вшивается через `include_str!` в `run_chez_sidecar`. По сети разрешён только loopback (`127.0.0.1`); тесты сетевых уроков поднимают сервер во `fork-thread`, а клиент подключается из главного потока; порты — через `tcp-listen`/`udp-bind!` на порту 0 и `local-port`.

## Формат урока

Файл урока — единый Markdown с frontmatter (YAML) и секциями:
- **frontmatter**: id, название, трек, порядок, навыки.
- **theory**: текст + подсвеченные примеры кода.
- **starter**: стартовый код для редактора.
- **tests**: автотесты как Scheme-код (R6RS); для треков-проектов — сценарии через sidecar/Chez.

**Конкретная кодировка** (парсер — `src/lib/lesson-parser.ts`, бандл — `src/lib/lessons.ts`): файлы лежат в `src/lessons/<track>/<id>.md`. Frontmatter от `---` до `---` в первой строке обязателен; поля `id`, `title`, `track` обязательны, `order` — число, `skills` — список строк. После frontmatter идёт theory (обычный Markdown); секции `starter` и `tests` отделяются строками `---starter` и `---tests` в начале строки. Примеры кода в theory — fenced-блоки с языком `scheme`; кнопка «Проверить» пока заглушка, запуск тестов — отдельный тикет.

**Навыки**: формализованы строковыми идентификаторами (например, `sockets`, `closures`). Версии навыков по уровням — вне MVP.

**Фазировка**: магистральный путь to-spec → to-tickets → implement. Первый кусок — каркас приложения + редактор + первый урок hello-world, проверяющий пайплайн «урок → код → запуск → вывод».
