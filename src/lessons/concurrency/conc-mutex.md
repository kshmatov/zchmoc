## Общие данные

Потоки разделяют данные программы. Если несколько потоков одновременно меняют одну и ту же переменную, результат может быть испорчен: операции «прочитал → посчитал → записал» накладываются друг на друга, и часть обновлений теряется. Такое состояние называется **гонкой**.

Посмотри на инкремент счётчика:

```scheme
(set! counter (+ counter 1))
```

Формально это три шага: прочитать `counter`, добавить `1`, записать обратно. Два потока могут прочитать одно и то же старое значение, оба записать одно и то же новое — и одно увеличение потеряется.

## Мьютекс

**Мьютекс** (от *mutual exclusion* — взаимное исключение) защищает общие данные: в один момент времени войти в «критическую секцию» может только один поток. Создаётся он через `make-mutex`, а вход защищается конструкцией `with-mutex`:

```scheme
(define lock (make-mutex))

(define (safe-inc!)
  (with-mutex lock
    (set! counter (+ counter 1))))
```

Пока один поток находится внутри `with-mutex`, остальные ждут, и обновление счётчика больше не теряется.

## Задание

Реализуй `safe-inc!` — безопасное увеличение значения в `box` на `1`. Мьютекс `m` уже создан (в Chez `box` — изменяемая ячейка: `(unbox box)` читает значение, `(set-box! box v)` записывает).

---starter
; Многозадачность · Урок 2 — Мьютексы и гонки
;
; ЗАДАНИЕ: реализуй safe-inc!, увеличивающую значение в box на 1.
; Оберни инкремент в (with-mutex m …), чтобы обновления не терялись.

(define m (make-mutex))

(define (safe-inc! box)
  (error 'conc "ЗАДАНИЕ: (with-mutex m (set-box! box (+ (unbox box) 1)))"))
---tests
(define b (box 0))
(let ((threads
        (map (lambda (k)
               (fork-thread
                 (lambda ()
                   (do ((i 0 (+ i 1))) ((= i 200))
                     (safe-inc! b)))))
             (make-list 10 #f))))
  (for-each thread-join threads))

(zchm-check-equal "десять потоков по двести инкрементов — ни одной потери"
                  (unbox b) 2000)
